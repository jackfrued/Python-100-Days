## .yaml .pyc文件 类型文件是啥，有啥作用，为啥打不开
### .yaml / .yml
- 是什么：一种“配置文件”格式（YAML Ain’t Markup Language），本质是纯文本。
- 作用：常用来写配置与数据，比如：
  - 项目配置（日志级别、数据库连接、策略参数）
  - CI/CD（GitHub Actions 也用 YAML）
  - 容器与服务编排（K8s/Helm 等）

### .pyc
- 是什么：Python 把 .py 源码编译出的字节码缓存（bytecode），通常在 __pycache__/ 里。
- 作用：
加快下次导入模块的速度（省去重复编译）
属于运行时缓存，不是源码
- 为什么打不开/看不懂：
.pyc 是二进制字节码，不是给人直接阅读的文本。
- 要不要提交到 GitHub：
通常不要。应在 .gitignore 里忽略：
- 能不能“反编译”：
理论上有工具能尝试还原，但结果不可靠且涉及安全/合规问题；正常开发应保留 .py 源码即可。

## vscode里面的灰色文件夹、文件名和灰色的代码段表示啥意思

A. 文件/文件夹被 .gitignore 忽略（最常见）
__pycache__/、.pyc、.venv/、dist/ 等经常显示为灰色（取决于设置）。
验证方式：
在项目根目录开终端（PowerShell）：
如果显示 !! __pycache__/ 之类，说明它被忽略。
B. VS Code Explorer 的“排除/隐藏”规则导致弱化
files.exclude、search.exclude、explorer.excludeGitIgnore 等设置会影响显示。
你可以在设置里搜：
excludeGitIgnore
files.exclude
search.exclude
C. 灰色代码段：未使用/不可达/被条件编译影响等
常见灰色代码表示：

未使用的 import / 变量 / 函数参数（lint 提示）
不可达代码（例如 return 后面）
被 # type: ignore 或条件语句影响（取决于语言服务）
在不同语言模式下被识别为注释或无效段


## websocket知识
3.1 WebSocket 是什么？
WebSocket 是一种建立在 TCP 之上的全双工通信协议。
特点：客户端与服务器建立一次连接后，可以持续保持连接，双方随时互相推送消息。
对比 HTTP：

HTTP 多数场景是“请求-响应”，服务器不能主动推消息（除非轮询/长轮询/SSE 等变体）。
WebSocket 更适合实时数据流：行情、盘口、成交、订单回报。
3.2 为什么量化交易常用 WebSocket？
常见用途：

实时行情推送：tick/逐笔成交、盘口深度（order book）、K线更新
账户/订单事件：下单结果、撤单回报、持仓变化
目标：降低延迟、减少轮询开销、保持消息连续性
3.3 关键概念与知识点
(1) 握手（Handshake）

WebSocket 连接是从一次 HTTP 请求升级而来：Upgrade: websocket
成功后协议切换为 WebSocket，走帧（frame）通信。
(2) 消息帧（Frame）与消息类型

文本帧（JSON 最常见）
二进制帧（更省流量/更快，但处理复杂）
(3) 心跳与保活（Ping/Pong）

长连接会遇到 NAT/防火墙超时，必须定期心跳避免断开。
交易所/行情服务通常要求客户端定期发送 ping 或业务心跳包。
(4) 断线重连与状态恢复 必须考虑：

网络抖动导致断线
重连后如何：
重新订阅频道（subscribe）
获取缺失数据（比如用 REST 拉一份最新快照 + 从序列号继续增量）
去重/按序处理消息（sequence id）
(5) 订阅模型

连接建立后通常要发送订阅请求：
订阅 BTCUSDT 的 depth、trade、kline 等
服务端会按频道推送。
(6) 流控与背压（Backpressure）

行情非常快：如果你处理不过来，消息会堆积导致延迟越来越大。
需要：
用队列/异步消费
丢弃策略（例如只保留最新盘口）
限频/合并更新
(7) 安全与鉴权

公共行情频道通常无需鉴权
私有频道（账户/订单）通常需要：
API Key + 签名
时间戳
使用 wss:// 加密
3.4 Python 里怎么用（方向建议）
常用库：

websockets（纯 async，轻量）
aiohttp（HTTP + WS 一体）
交易所 SDK（封装订阅/重连/签名）
